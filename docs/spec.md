# キャレット棒人間エディタ 仕様書

Sep 26, 2026 作成 · @mt-sumikko

## 概要

テキスト入力中に表示される点滅キャレット(カーソル)を、棒人間のアニメーションキャラクターに置き換える。

- 打鍵中は「歩いている/走っている」モーション
- 何もしていない時は「待機」モーション(3段階...静かに待つ、煽る、飽きて座る )
- 改行や行を跨ぐ移動では「ジャンプ」
- 文字を消す時は「放り投げる」モーション

絵柄の方向性

Do：鉛筆で描いたような揺らぎ・不完全さ・手の温度を感じる質感

Don't：SVGできれいに描けるような幾何学的な線

既存事例を調査した結果、「キャレットを状態を持つキャラクターに置き換える」事例はほぼ見当たらず、独自性のあるアイデアとして進めることにした。

MVPの最終アウトプット：

- キャレットが棒人間になって動く体験に特化した、自作のシンプルなエディタ（すぐ遊べるWebページ)
  - ログイン（アカウント登録）なし
  - 打った内容を自動保存（localStorage）、初回だけ「このブラウザに自動保存されます」と伝える
  - 入力した内容を.txt / .mdでダウンロード可能
- ロリポップ！デプロイナウコンテストへの応募を考慮して上記の形を優先
- 既存のコードエディタライブラリ(CodeMirror/Monacoなど)への統合は、将来的な発展先として残す。

## 実装方針

### アニメーションの骨格: 手続き型(procedural)

&#91;embedded content: 棒人間の座標点10つ(肩を追加)と、実際に描画されるpath4つの対応\]

絵(フレーム)そのものを並べる方式ではなく、頭・体・腕・脚の座標を毎フレーム計算式で出して線で結ぶ方式を採用。作業量を抑えたまま、状態間の繋ぎをなめらかさを守るため。

### 線の質感: rough.js + 静的テクスチャ画像によるマスク

比較検証の結果、以下の組み合わせに決定:

1. **rough.js**: 線の頂点座標をランダムに揺らして手描き風の形にするライブラリ。「ラフさ」「歪み(bowing)」「線の太さ」のパラメータで調整
2. **静的テクスチャ画像 + SVG `<mask>`**: 鉛筆の擦れ・紙の目を表現する画像を1枚用意し、線の形はそのままに、線の中身だけをその画像の濃淡で透明度変調(マスク)する

rough.jsの暫定パラメータ値：

- ラフさ(roughness) : 1.7
- 歪み(bowing): 1.5&#32;
- 線(strokeWidth)の太さ 4.0

テクスチャ画像は現状プレースホルダー(生成ノイズ→実写の鉛筆テクスチャ写真で試した)で、本番用の素材は改めて描き起こす予定。

注意: 上記の暫定値は比較検証ツール側の座標系(viewBox `-100 -220 200 300`)で調整した値。実プロトタイプ(`caret-stickman-editor.html`)の座標系はviewBox `-20 -44 40 60`で、これは比較ツールのちょうど1/5スケール。rough.jsのパラメータもviewBoxの目盛りに対する量なので、実プロトタイプで使う値は単純に**5で割ればよい**: ラフさ 0.34 / 歪み 0.3 / 線の太さ 0.8。

フォントサイズ変更への追従について: プロトタイプは`viewBox`自体は固定したまま、CSSの表示サイズ(width/height)だけをフォントサイズに連動させる設計になっている。SVGの`viewBox`はスケール(目盛りの意味)を固定するものなので、**この設計を保つ限り、rough.jsのパラメータは固定値のままでフォントサイズの変化に自動追従する**(都度換算する必要はない)。Codeへ引き継ぐ際は「viewBoxを固定し、表示サイズだけを可変にする」設計を崩さないこととセットで伝える。

比較検証用プロトタイプ: [手描きテクスチャ比較](https://claude.ai/artifact/1TNEJBr4MGg55yZJ13bvGo)

## 条件別モーション一覧(現時点で定義済み)

以下はプロトタイプ([キャレット棒人間エディタ](https://claude.ai/artifact/D7gbUY36XXda8pFzsuAC6Z))で実装済みの全状態。実際には「入力イベント網羅性チェック表」の通り実装しきる。

| 動作・状態 | 発生条件 | 内容 |
| --- | --- | --- |
| 短い待機 | 入力/移動が300ms以上ない(通常時のデフォルト) | 腕を上げて「キャレットのフリ」をするポーズ。腕を上げ直す動きは約0.2秒かけてゆっくり、下ろすのは即座 |
| 短い待機(文字の間) | 短い待機中、かつキャレットの後ろに文字がある | 腕・膝・脚を中心軸に寄せ、頭も楕円に潰して「横から見た棒」に近い、より細いシルエットにする |
| 打っている(歩き/走り) | 300ms以内に入力または移動があった | 4コマの歩行サイクル(接地→振り出し中→接地(反転)→振り出し中)をスナップ切替。前後2コマの単純な入れ替えだと左右対称ゆえに絵が変わらないバグを踏んだため。直近の移動間隔から歩き⇔走りを判定し、コマ間隔・歩幅・弾みの大きさを連動させる |
| 長い待機(煽り) | 30秒以上、真に何も動いていない | 体重を左右に移しながら片腕ずつ上げる、挑発的な大きいモーション |
| あきらめて着席 | 長い待機が始まってから5分経過 | 煽りモーションから、なめらかに(数秒かけて)しゃがみ込むポーズへ遷移。腰が下がり膝が曲がり頭も少し垂れる |
| 改行/行を跨ぐジャンプ | Enterキー(変換確定時は除く)、またはBackspaceでの行結合・矢印キー・クリックなど、キャレットが行を跨いで動く全てのケース(IME変換中は対象外) | 助走(その場で踏み込む・約130ms)→跳躍(弧を描いて上下・約350ms、空中では膝を曲げて足を引き上げる)→着地の踏ん張り(着地の瞬間に最大まで曲げ、そこから伸び上がる・約220ms)の3段階。位置移動(次の行へ)は助走が終わったタイミングで、跳躍の時間に合わせて移動する。※Backspaceによる行結合の場合のみ、このフルセットではなく「削除(放り投げ)」に小さい跳ねを重ねた簡易版に統合される |
| 削除(放り投げ) | Backspace/Deleteで文字を削除した時(IME変換中の内部的な削除イベントは除く) | 両手を画面左に寄せて掴み、片足を大きく踏み込みながら画面右へ振り抜く「全力で放り投げる」ジェスチャー(約220ms)。※Backspaceによる行結合の場合は、これに小さい上下の跳ねを重ねた簡易版になる(改行ジャンプのフルセットは省略) |
| 変換中の表示 | IME変換中(compositionstart〜compositionend) | 棒人間の不透明度を0.12まで落とし、ほぼ見えない薄い状態にする(変換候補の文字と被らないようにするため) |
| 複数文字ホップ | 同一行内で1.5文字以上の大きな横移動(Home/End・単語単位の移動・遠距離クリックなど。IME変換中は除く) | 移動方向へ、肘に引っぱられるように飛び出す(約240ms)。※当初の「変換確定ホップ」(compositionend専用)は廃止してこのルールに統合。変換確定では特別なモーションは出さない |
| 常時: line boil | 常時(全状態に重畳) | 補間せず一定間隔(40ms)でランダムに座標を切り替える、手描きコマ撮り風の微振動 |
| フォーカス外れ | エディタからblur | line boilを止め、opacityを0.5まで落とす |
| フォーカス復帰 | エディタにfocus | line boilを再開し、opacityを1に戻す(blurの逆) |
| リサイズ/フォントサイズ変更 | windowのresizeイベント | updateFigurePosition()を呼び直し、既存の移動ルール(同一行スライド/行またぎジャンプ)をそのまま適用する |

サイズ・距離の調整:

- 棒人間のサイズ：エディタのフォントサイズに連動
- 棒人間の横位置：キャレットと文字との横方向の距離は、後ろに文字が「ある/ない」で自動的に切り替える(間にいる時は詰める、行末ではやや離す)
- 棒人間の縦位置：文字の行（ベースライン）に揃える

# その他メモ（意思決定・検証記録等）

## 実装方針の判断

### アニメーションの骨格

- 手続き型であれば、以下をすべて数値の補間だけで実現できることを、プロトタイプで確認済み
  - 腕を上げ直す速度
  - 座り込みへのブレンド
  - 踏み込み→着地のイージング、歩き⇔走りの速度連動
- 手描きPNGコマ送り方式だと、状態の組み合わせの数だけ繋ぎのコマ絵を用意する必要があり作業が多くなる。不十分だと状態切替時にポーズが飛ぶ。

### 線の質感

却下した方式とその理由:

- **SVGフィルター(****`feTurbulence`****のライブ生成)**: 線の形が変わるたび(rough.jsの再生成やline boilの座標変更のたび)に、ノイズ計算からフィルター全体を毎回やり直す必要があり、負荷が高い。テクスチャ画像を静的にしてマスクとして使えば、画像は1回デコードするだけで済み、形がどれだけ変わっても再計算が発生しない
- **displacementによる形の歪み**(ラフさの表現)と**鉛筆の擦れ・粒感**(テクスチャの表現)は別軸の問題であり、混同しないよう区別した

関連: 入力イベント網羅性チェック (テキスト入力で起こり得る事象の洗い出しと、現状の対応状況)

## モーション実装でハマった/ハマりそうなポイント

- **左右対称の入れ替えは「絵が変わらない」**: 歩行モーションを「前脚と後ろ脚の座標を2コマで入れ替える」だけで実装したところ、棒人間は左右の脚が同じ形で描画される(左右の区別がない)ため、入れ替えても画面上の絵が完全に同じになってしまうというバグを踏んだ。実際には座標(データ)は変わっているのに絵が変わらないので発見しづらい。**対策**: 前⇄後ろの2コマだけでなく、間に「片方の脚が浮いて振り出し中」の非対称な中間ポーズを挟んだ4コマ構成にする必要がある
- **脚の長さも揃える必要がある(腕と同様)**: 前脚・後ろ脚・支え脚・ニュートラル時で、腰から足までの距離がバラバラだと、真横のプロファイルのはずが「脚が手前(カメラ側)に飛び出してきているように見える」歪みが発生する。腕の長さ統一と同じ考え方で、脚も腰からの距離を揃える必要あり
  - →対応済み。前後の接地脚(歩き/走り)を、腰からの距離が揃うよう再計算して調整した(両ファイルに反映済み(実エディタにも4コマ歩行を移植する際、同じ考え方で長さを揃えた))
- **腕の付け根は首ではなく肩(胴の途中)**: 参考の手描き画像を分析した結果、腕は首(胴の一番上)からではなく、\*\*胴の途中(鎖骨あたり)\*\*から生えていて、手は斜め下に垂れていた。これに合わせて座標系に`shoulder`(肩)という新しい点を追加し、腕の付け根を`neck`から`shoulder`に変更。最終的に胴の30%地点で確定し、両ファイルに反映済み
